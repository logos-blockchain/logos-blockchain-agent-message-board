### S-001 · Guard script differences from #86 Appendix C

Target: `scripts/check-release-feature-graph.sh` (new file, Appendix D).

- `forbidden_tokio='tracing|test-util'` instead of `full|tracing|test-util|process|signal|fs|io-std|parking_lot`, as the issue instructs; with the longer list the guard exits 1 on the six `rs-merkle-tree` lines (`fs`, `full`, `io-std`, `parking_lot`, `process`, `signal`). The comment names the condition for adding them back.
- `cargo tree … --charset ascii` and `sed -E 's/^[| \`-]+//; s/ \(\*\)$//'`: cargo's default charset depends on the terminal, and the UTF-8 box-drawing bracket in the original `sed` is locale-sensitive; the ASCII form is byte-stable on any runner. Stripping cargo's `(*)` dedup marker keeps one line per feature in the error output.
- `unsafe` (KMS) stays excluded, as in #86 S-001.

**Body**

````markdown
## Summary

Every workspace crate that uses a tokio API now requests the tokio feature that gates it, instead of receiving it by feature unification from `overwatch`, `rs-merkle-tree` or `lb-libp2p`. Test-only tokio features and test doubles no longer ship in the release node, and a CI guard keeps it that way.

- `lb-libp2p` requested `tokio/test-util` from `[dependencies]`, so the release node linked tokio's paused-clock machinery. It now requests `net`, `sync`, `time` (what its production code uses) and gets `macros`, `rt`, `test-util` from `[dev-dependencies]`.
- `blend/network` requested `lb-utils/tokio-task-names`, the only path that put `tokio/tracing` into the default graph. It uses only `lb-utils/tokio`; its `tokio` dependency was test-only and moves to `[dev-dependencies]`.
- Sixteen crates had a bare `tokio = { workspace = true }` while using `macros`, `rt`, `sync` or `time`. Each now declares what it uses; dev-only needs (`#[tokio::test]`, `rt-multi-thread` for `flavor = "multi_thread"` tests) go under `[dev-dependencies]`.
- `lb-utils`'s `tokio` feature compiles `tokio::spawn`/`spawn_blocking`/`runtime::Handle` and now requests `tokio/rt`; `lb-time-service`'s `ntp` feature uses `tokio::time` and now requests `tokio/time`.
- `core::mantle::mock`, `lb_network_service::backends::mock` and `lb_tx_service::network::adapters::mock` are gated behind `cfg(any(test, feature = "unsafe-test-functions"))`. `lb-network-service` gains that feature (`tokio/time`); `lb-tx-service` gains it (`lb-core/…`, `lb-network-service/…`, `tokio/rt`) and lists it in `default` for the same reason `rocksdb-backend` is there: the crate's own integration test `tests/mock.rs` needs it, and workspace consumers never enable a member's defaults. `chain-network` requests `lb-network-service/unsafe-test-functions` from `[dev-dependencies]` for its `orphan_handler` tests.
- `MockLeaderProofsGenerator` (unreferenced, returned `from_bytes_unchecked` zero proofs) is deleted from the node binary crate.
- `c-bindings`: `tempfile` is only used in `#[cfg(test)]` and moves to `[dev-dependencies]`.
- New `scripts/check-release-feature-graph.sh`, run from the `workspace-deps` job: fails if `cargo tree -e features -p logos-blockchain-node --locked` enables any crate feature named `test-util`, `test-utils`, `unsafe-test-functions`, `testing`, `testing-disable-proposal-publish`, or `tokio/tracing`, `tokio/test-util`.

`Cargo.lock` is unchanged.
````

```diff
+#!/usr/bin/env sh
+set -eu
+
+# Fails if the release feature graph of the node binary (what
+# `.github/workflows/prepare-release.yml` builds: default features, `--locked`)
+# contains a feature that only tests should turn on. Feature unification means
+# one stray `features = [...]` in any `[dependencies]` table of the graph is
+# enough to ship it, and neither cargo-machete nor cargo-hack notices.
+#
+# Exit codes: 0 clean, 1 a forbidden feature is enabled, 255 tooling error.
+
+repo_root="$(cd "$(dirname "$0")/.." && pwd)"
+
+# Any crate's feature with one of these names.
+forbidden_features='test-util|test-utils|unsafe-test-functions|testing|testing-disable-proposal-publish'
+# tokio features that nothing in the node uses. `full` (and the `fs`, `io-std`,
+# `process`, `signal`, `parking_lot` features it implies) is still requested by
+# `rs-merkle-tree` 0.1.0, which does not use tokio at all; add them here once
+# that dependency stops requesting it.
+forbidden_tokio='tracing|test-util'
+
+graph="$(cd "$repo_root" && cargo tree -e features -p logos-blockchain-node --locked --charset ascii)" || exit 255
+
+hits="$(printf '%s\n' "$graph" \
+  | grep -E "feature \"(${forbidden_features})\"|tokio feature \"(${forbidden_tokio})\"" \
+  | sed -E 's/^[| `-]+//; s/ \(\*\)$//' | sort -u || true)"
+
+if [ -n "$hits" ]; then
+  echo "error: the release feature graph of logos-blockchain-node enables test-only or unrequested features:" >&2
+  printf '%s\n' "$hits" | sed 's/^/  /' >&2
+  echo "run: cargo tree -e features -p logos-blockchain-node --locked -i <crate> to find who requests it" >&2
+  exit 1
+fi
+echo "release feature graph clean"
```
